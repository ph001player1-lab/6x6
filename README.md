# Шесть из шести · 6×6

Telegram Mini App: шесть вопросов, и вы видите всех в базе, с кем совпали и по каким сферам.
Написать можно после того, как человек примет запрос на контакт.

```
db/schema.sql            вся база: таблицы, доступы, функции, триггеры, расписание
functions/auth           проверка подписи Telegram, выдача токена
functions/bot            вебхук: кнопки «Принять / Отклонить», приглашения
functions/pusher         очередь сообщений бота, раз в минуту
functions/export         выгрузка базы в Excel, бот присылает файл
web/                     сам мини-апп: index.html, app.js, qr.js
migrate/                 слияние двух старых баз
```

## 1. Бот

У [@BotFather](https://t.me/BotFather): `/newbot` — забрать токен. Затем `/newapp`, выбрать бота, короткое имя приложения `app`. Адрес впишем на шаге 4.

## 2. Supabase

1. Новый проект. **SQL Editor** → вставить `db/schema.sql` целиком → Run.
2. Прописать себя администратором:
   ```sql
   insert into admins (tg_id) values (ВАШ_TELEGRAM_ID);
   ```
   ID узнать у [@userinfobot](https://t.me/userinfobot).
3. **Settings → API** — скопировать `Project URL` и ключ `anon`.
4. **Settings → API → JWT Secret** — понадобится на следующем шаге.

## 3. Edge Functions

```bash
npx supabase link --project-ref ВАШ_REF

npx supabase secrets set \
  BOT_TOKEN=токен_от_BotFather \
  APP_JWT_SECRET=jwt_secret_из_настроек_supabase \
  APP_URL=https://t.me/ИМЯ_БОТА/app \
  WEBHOOK_SECRET=любая_строка

npx supabase functions deploy auth   --no-verify-jwt
npx supabase functions deploy bot    --no-verify-jwt
npx supabase functions deploy export --no-verify-jwt
npx supabase functions deploy pusher
```

`--no-verify-jwt` у первых трёх обязателен: `auth` вызывается **до** появления токена, `bot` дёргает Telegram, `export` проверяет права сам по таблице `admins`.

Подключить вебхук бота:

```bash
curl "https://api.telegram.org/bot<ТОКЕН>/setWebhook?url=https://<REF>.supabase.co/functions/v1/bot&secret_token=<WEBHOOK_SECRET>"
```

Запустить разгребание очереди — в SQL Editor, подставив свои значения:

```sql
select cron.schedule('pusher', '* * * * *', $$
  select net.http_post(
    url := 'https://ВАШ_REF.supabase.co/functions/v1/pusher',
    headers := '{"Authorization":"Bearer СЕРВИСНЫЙ_КЛЮЧ","Content-Type":"application/json"}'::jsonb,
    body := '{}'::jsonb);
$$);
```

По желанию — еженедельная выгрузка себе в чат:

```sql
select cron.schedule('backup', '0 6 * * 1', $$
  select net.http_post(
    url := 'https://ВАШ_REF.supabase.co/functions/v1/export',
    headers := '{"Authorization":"Bearer СЕРВИСНЫЙ_КЛЮЧ","Content-Type":"application/json"}'::jsonb,
    body := '{"scheduled":true}'::jsonb);
$$);
```

## 5. Перенос старых баз

```bash
pip install openpyxl
python3 migrate/build.py Earth_Genesis.xlsx migrate/love_lottery.csv > migrate/import.sql
```

Скрипт печатает в начале файла отчёт: сколько человек в каждой базе, сколько пересеклось и у кого ответы разошлись. Дальше `import.sql` выполняется в SQL Editor.

Что он делает:

- В Genesis один человек занимает несколько строк, если менял город. Берётся последняя запись по времени.
- Если человек есть в обеих базах, побеждают более свежие ответы.
- Названия вариантов Genesis и шесть цифр лотереи сводятся к одному виду `c1…c6`.
- Очередь сообщений очищается в конце — иначе импорт разошлёт всем пуши о новых совпадениях сразу.

На ваших двух выгрузках вышло: 34 человека из Genesis, 14 из лотереи, 3 пересечения, итого **45 человек и 43 конфигурации**. Две пары на 6 из 6. Людей без единого совпадения — ноль.

Буквенные коды взяты из Genesis (`MNG`, `PLY`, `PRT`, `CNS`), чтобы у тех, кто уже знает свой код, он не поменялся.

## Как это устроено

**Без шести ответов в базу не попасть.** Строка игрока создаётся только функцией `save_answers`, и только целиком. Заглянуть «посмотреть» и оставить пустой профиль нельзя — гистограммы улья остаются честными.

**Ник скрыт до согласия.** Сразу видно имя, фото, счёт и разбор по сферам. `@ник` появляется только после принятого запроса. Это не украшение: показать ник — значит уже дать контакт, и тогда согласие превращается в декорацию.

Приватность держится на правилах доступа в самой базе, а не на коде фронта: под ролью авторизованного пользователя в таблице игроков видна ровно одна строка — своя. Всё остальное отдают функции, которые вырезают ник, если контакт не открыт. Даже прямые запросы к API в обход приложения ников не дадут.

**Скан — это уже обоюдное согласие.** Оба стоят рядом, поэтому один скан открывает контакт сразу, без запроса.

**Счёт нигде не хранится.** Он пересчитывается по текущим ответам обоих при каждом показе. Поэтому смена ответов посреди вечера обновляет все прошлые совпадения, а накрутить счёт с телефона нельзя.

**Расстояние — корзинами.** «Рядом», «в районе», «в городе». Точное расстояние позволяет вычислить чей-то адрес по трём замерам из разных точек; на этом горели крупные приложения знакомств. Координаты хранятся округлёнными до трёх знаков и стираются через шесть часов.

**Совпадения ищутся по индексу, а не перебором.** Счёт 4 и выше — это ровно 353 конфигурации вокруг вашей: 1 своя, 28 на расстоянии одной оси, 324 на расстоянии двух. На замерах при 40 000 игроков: сводка главного экрана 20 мс, список по счёту 8 мс, список по сфере 1 мс.

Полный расклад пространства, сумма даёт ровно 30 240:

| Совпадение | Конфигураций |
|---|---|
| 6 из 6 | 1 |
| 5 из 6 | 28 |
| 4 из 6 | 324 |
| 3 из 6 | 1 982 |
| 2 из 6 | 6 755 |
| 1 из 6 | 12 150 |
| 0 из 6 | 9 000 |

**QR не зависит от сети.** Генератор свой, без внешних библиотек: код игрока рисуется и читается даже когда вайфай в баре лежит.

## Если что-то не так

| Симптом | Причина |
|---|---|
| «Подпись не сошлась» | `BOT_TOKEN` от другого бота, чем тот, у которого прописан адрес приложения |
| «Справочник вопросов пуст» | `schema.sql` не выполнен целиком |
| Вкладки «Админ» нет | вашего Telegram ID нет в таблице `admins` |
| Сообщения бота не доходят | человек не запускал бота; в админке это видно как «Бот доходит» |
| Очередь растёт | не заведено расписание `pusher` или в нём неверный сервисный ключ |
| Геолокация не срабатывает | старый клиент Telegram; поле «место» текстом работает всегда |
